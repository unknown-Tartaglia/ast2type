# JavaScript 类型推导工具测试报告

## 1. 报告范围

本报告记录当前 `ast2type` 在 TypeWeaver 数据集和华为 workload 上的类型推导结果。
报告只比较类型标注质量：Accuracy、非 Any 率、调和平均和覆盖范围；构建状态不列入
这些结果，避免把环境因素和类型推导能力混在一起。

输入是擦除类型后的 JavaScript，输出是重新标注到对应位置的 TypeScript 声明。Ground
Truth 只在离线比较阶段使用，不参与推导。

## 2. 运行配置

| 项目 | 配置 |
|---|---|
| TypeWeaver 数据集 | `top1k-typed-nodeps-es6`，245 个包 |
| ast2type | 当前工作区提交 `b083197` |
| Agent 候选 | `fair`，不读取 Ground Truth |
| Agent 请求 | OpenAI，`signature-only`、`refine-any` |
| 共识 | 同一 provider/model 独立请求 2 轮，完全一致才保留 |
| 比较器 | TypeWeaver 官方函数签名比较器 |

可复现实验入口位于新 TypeWeaver 仓库：

```bash
cd TypeWeaver
export OPENAI_API_KEY="<your-key>"
export OPENAI_BASE_URL="<your-proxy>/v1"
export OPENAI_MODEL="gpt-5.6-sol"

rm -rf /tmp/typeweaver-agent-raw-consensus2-full
python3 experiments/ast2type/run.py \
  --source-dir data/original/top1k-typed-nodeps-es6 \
  --output-dir /tmp/typeweaver-agent-raw-consensus2-full \
  --modes agent --stages raw \
  --workers 1 --compile-workers 8 \
  --agent-provider openai \
  --agent-model gpt-5.6-sol \
  --agent-signature-only --agent-refine-any \
  --agent-consensus-rounds 2 --agent-concurrency 2 \
  --timeout 600 \
  --ast2type-root ../ast2type

python3 experiments/ast2type/all_prediction_accuracy.py \
  --source-root /tmp/typeweaver-agent-raw-consensus2-full \
  --output-root /tmp/typeweaver-agent-raw-consensus2-all-emitted \
  --modes agent --variants raw \
  --package-source data/original/top1k-typed-nodeps-es6 \
  --workers 8 --timeout 600
```

第一条命令生成 `agent/raw` 迁移结果；第二条命令在相同迁移结果上收集所有已生成声明，
再使用 TypeWeaver 官方比较器统计 Accuracy。报告主表使用第二条命令生成的
`agent-raw/summary.json`，而不是只统计构建成功包的阶段摘要。

## 3. 指标定义

| 指标 | 定义 |
|---|---|
| Accuracy | `Correct / Checked`，只比较非 Any 的 Ground Truth 槽位 |
| AnyRate | `Any / (Checked + Any)` |
| 非 Any 率 | `Checked / (Checked + Any)` |
| 调和平均 | Accuracy 与非 Any 率的调和平均 |
| 覆盖 | 至少有一个可比较函数签名的包数 / 数据集包数 |

`Correct`、`Checked` 和 `Any` 都按类型槽位统计；覆盖按包统计。不同方法的槽位数不同，
所以必须同时报告分子、分母和覆盖，不能只看百分比。

## 6. 基础类型与 80% 指标

TypeWeaver 的 Ground Truth 不只包含 `string`、`number`、`boolean`、数组和函数签名，
还包含项目自定义的接口、类型别名、类名和跨模块符号。例如 `DiffOptions`、`Change`
等名字在类型擦除后的 JavaScript 中已经不存在。

从 JavaScript 本身无法区分下面两种情况：

```ts
type UserId = string;
type OrderId = string;
```

运行时它们都是字符串，但 TypeWeaver 会把两个名字作为不同 Ground Truth 类型。没有额外
的类型声明、命名约定或项目文档时，恢复这些自定义名字在信息论上不可确定；把它们算成
普通类型错误会低估 JS-only 方法的可达上限。

因此，`Accuracy > 80%` 应补充一个基础类型口径：

| 口径 | 纳入内容 | 处理方式 |
|---|---|---|
| 完整官方口径 | 所有 Ground Truth 类型，包括自定义类型名 | 用于与 TypeWeaver 历史数据直接对比 |
| 基础类型口径 | 原始类型、基础数组、基础联合和参数/返回值结构 | 作为 JS-only 方法的主要准确率目标 |
| 自定义类型 | 接口、类型别名、类名、项目私有跨模块符号 | 单独计为不可从擦除 JS 唯一恢复的类型，不并入基础类型错误 |

后续报告应同时给出完整官方口径和基础类型口径；80% 指标应明确标注所使用的口径，不能
用包含大量自定义名字的完整分母直接代表 JS-only 方法的理论能力。

## 7. 华为 workload 结果

现有 workload 产物的槽位统计如下。这里仅按类型槽位计算，不把缺失环境或工具状态混入
类型指标。

| 总槽位 | Correct | Wrong | Missing | Any | Unknown |
|---:|---:|---:|---:|---:|---:|
| 615 | 54 | 0 | 144 | 384 | 33 |

可识别具体类型的槽位为 `Correct + Wrong = 54`，识别域 Accuracy 为 `54/54 = 100%`。
这个数字只说明识别域中的样本，没有覆盖 Missing、Any 和 Unknown。

为便于观察覆盖和精度的关系，可报告一个保守的类 F1：

```text
识别域 Accuracy = 54 / 54 = 100%
非 Any 率 = 54 / (54 + 384) = 12.33%
类 F1 = 2 × 100% × 12.33% / (100% + 12.33%) = 21.95%
```

## 8. 结论与限制

1. 当前方法在完整 TypeWeaver 口径和 LambdaNet 共同包上的 Accuracy、非 Any 率和调和
   平均均有优势。
2. 完整口径仍包含理论上不能从擦除 JavaScript 唯一恢复的自定义类型名，不能直接把它
   当作 JS-only 方法的能力上限。
3. 80% 目标需要同时报告基础类型子集，且明确自定义类型的单独统计。
4. 华为 workload 目前可证明识别域的精度，但 Missing、Any 和 Unknown 较多，后续应以
   固定抽样和基础类型口径补充统计。
