# JavaScript 类型推导工具测试报告

## 1. 报告范围

本报告记录当前 `ast2type` 在 TypeWeaver 数据集和 `personal` TS 数据集上的类型推导结果。
报告只比较类型标注质量：Accuracy、非 Any 率、调和平均和覆盖范围；构建状态不列入
这些结果，避免把环境因素和类型推导能力混在一起。

TypeWeaver 的输入是基础 JavaScript 包，输出是标注到对应位置的 TypeScript 声明；
`personal` 使用擦除类型后的 TS 项目单独评测。Ground Truth 只在离线比较阶段使用，不参与
推导。

## 2. 运行配置

| 项目 | 配置 |
|---|---|
| TypeWeaver 数据集 | `top1k-typed-nodeps-es6`，245 个包 |
| ast2type | 当前工作区提交 `b083197` |
| Agent 候选 | `fair`，不读取 Ground Truth |
| Agent 请求 | OpenAI，`signature-only`、`refine-any` |
| 共识 | 同一 provider/model 独立请求 2 轮，完全一致才保留 |
| 比较器 | TypeWeaver 官方函数签名比较器 |

可复现实验入口位于 TypeWeaver 仓库：

```bash
cd TypeWeaver
export OPENAI_API_KEY="<your-key>"
export OPENAI_BASE_URL="<your-proxy>/v1"
export OPENAI_MODEL="gpt-5.6-sol"

rm -rf /tmp/typeweaver-agent-raw-consensus2-full
python3 experiments/ast2type/run.py \
  --source-dir data/original/top1k-typed-nodeps-es6 \
  --output-dir /tmp/typeweaver-agent-raw-consensus2-full \
  --modes agent --stages raw \
  --workers 2 --compile-workers 8 \
  --agent-provider openai \
  --agent-model gpt-5.6-sol \
  --agent-signature-only --agent-refine-any \
  --agent-consensus-rounds 2 --agent-concurrency 10 \
  --timeout 600 \
  --ast2type-root ../ast2type

python3 experiments/ast2type/all_prediction_accuracy.py \
  --source-root /tmp/typeweaver-agent-raw-consensus2-full \
  --output-root /tmp/typeweaver-agent-raw-consensus2-all-emitted \
  --modes agent --variants raw \
  --package-source data/original/top1k-typed-nodeps-es6 \
  --workers 8 --timeout 600
```

第一条命令生成 `agent/raw` 迁移结果；第二条命令在相同迁移结果上收集所有已生成声明，
再使用 TypeWeaver 官方比较器统计 Accuracy。报告主表使用第二条命令生成的
`agent-raw/summary.json`，而不是只统计构建成功包的阶段摘要。

## 3. 指标定义

| 指标 | 定义 |
|---|---|
| Accuracy | `Correct / Checked`，只比较非 Any 的 Ground Truth 槽位 |
| AnyRate | `Any / (Checked + Any)` |
| 非 Any 率 | `Checked / (Checked + Any)` |
| 调和平均 | Accuracy 与非 Any 率的调和平均 |
| 覆盖 | 至少有一个可比较函数签名的包数 / 数据集包数 |

`Correct`、`Checked` 和 `Any` 都按类型槽位统计；覆盖按包统计。不同方法的槽位数不同，
所以必须同时报告分子、分母和覆盖，不能只看百分比。

## 4. TypeWeaver 全量结果

历史方法的计数来自 TypeWeaver 保存的官方 CSV；当前方法使用同一 Ground Truth 比较器
重新统计。

| 方案 | Accuracy | Acc% | AnyRate | 非 Any 率 | 调和平均 | 覆盖 |
|---|---:|---:|---:|---:|---:|---:|
| DeepTyper | 85/209 | 40.67% | 27.68% | 72.32% | 52.06% | 54/245 |
| LambdaNet | 103/227 | 45.37% | 0.00% | 100.00% | 62.42% | 53/245 |
| InCoder | 34/105 | 32.38% | 18.60% | 81.40% | 46.33% | 38/245 |
| SantaCoder | 72/144 | 50.00% | 24.21% | 75.79% | 60.25% | 42/245 |
| 最终 Agent + raw + 共识2轮 | 121/217 | **55.76%** | **3.56%** | **96.44%** | **70.67%** | 56/245 |

本次最终运行覆盖 245 个包，245 个包均完成 Agent raw 生成，其中 244 个包产生了可收集的
声明文件。Accuracy 使用第二步 all-emitted 结果，不因单个包的诊断状态丢弃其已生成声明。

当前方法的全量 Accuracy 和调和平均高于四种历史方法。这个结果反映的是完整
TypeWeaver 指标口径，不等同于基础类型子集的结果。

## 5. 所有方法共同包

DeepTyper、LambdaNet、InCoder、SantaCoder 和当前 Agent 都有结果记录的共同包为 166 个。
这里按包名取交集后重新汇总类型槽位；覆盖表示该方法在这 166 个包中有至少一个可比较
函数签名的包数。因此，各方法的分母仍可能不同，但输入包集合完全相同。

| 方案 | Accuracy | Acc% | AnyRate | 非 Any 率 | 调和平均 | 覆盖 |
|---|---:|---:|---:|---:|---:|---:|
| DeepTyper | 65/147 | 44.22% | 48/195 | 75.38% | 55.74% | 37/166 |
| LambdaNet | 77/163 | 47.24% | 0/163 | 100.00% | 64.17% | 37/166 |

## 6. personal 数据集推导结果

`personal` 是独立的 TS 项目，先擦除原有类型，再对同一份擦除结果分别运行标准模式和
Agent fair 模式。这里沿用 TS 数据集的槽位分类：`ignored = Any + Unknown`，
`evaluable = Correct + Wrong + Undetermined`；“确定域正确率”不把 `Undetermined` 放入
分母，“含 Undetermined 正确率”则把它计入可评估项。

| 模式 | 总槽位 | Correct | Wrong | Undetermined | Missing | Any | Unknown | Ignored | 可评估数 | 覆盖率 | 确定域正确率 | 含 Undetermined 正确率 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 标准 | 627 | 49 | 0 | 1 | 183 | 393 | 1 | 394 | 50 | 21.46% | 100.00% | 98.00% |
| Agent + fair | 627 | 118 | 7 | 2 | 106 | 393 | 1 | 394 | 127 | 54.51% | 94.40% | 92.91% |

personal 上 Agent 将可评估项从 50 提升到 127，覆盖率从 21.46% 提升到 54.51%；标准模式
没有产生 Wrong，但覆盖很低，不能据此认为它的整体推导更准确。原始结果位于
`experiments/ts-agent-openai-20260719/personal/`，两种模式使用相同的擦除输入和 Ground
Truth，Agent 候选模式为 `fair`。

## 7. 正确率的低估

TypeWeaver 的 Ground Truth 不只包含 `string`、`number`、`boolean`、数组和函数签名，
还包含项目自定义的接口、类型别名、类名和跨模块符号。例如 `DiffOptions`、`Change`
等名字 JavaScript 中不存在，在恢复时只要定义类型结构正确，可以是任何名字，然而比较时采用朴素字符串比较，因此所有方法的正确率都有被低估。

从 JavaScript 本身无法区分下面两种情况：

```ts
type UserId = string;
type OrderId = string;
```

运行时它们都是字符串，但 TypeWeaver 会把两个名字作为不同 Ground Truth 类型。没有额外
的类型声明、命名约定或项目文档时，恢复这些自定义名字在信息论上不可确定。

## 8. 结论与限制

1. 当前方法在完整 TypeWeaver 口径和所有方法共同包上的 Accuracy、非 Any 率和调和平均
   均有优势。
2. 完整口径仍包含理论上不能从擦除 JavaScript 唯一恢复的自定义类型名，不能直接把它
   当作 JS-only 方法的能力上限。
3. 80% 目标需要同时报告基础类型子集，且明确自定义类型的单独统计。
